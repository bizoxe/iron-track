Contribution Guide¶

Setting up the environment¶

The easiest way to set up the development environment is to use the provided Makefile. This project requires Astral’s uv for dependency management.

  1. If you do not have uv installed, run: make install-uv

  2. Run the full installation command:

    make install

    This command re-creates the environment (an existing .venv is removed along with build artifacts), installs the project in editable mode, and sets up all development dependencies.

  3. Install pre-commit hooks:

    uv run pre-commit install --hook-type pre-commit --hook-type commit-msg

    This registers both hook stages locally: pre-commit (linters on staged files) and commit-msg (Conventional Commit format validation).

Tip

For detailed setup instructions and development workflows, see the Installation Guide and the Development Workflow.

Code contributions¶

Workflow¶

  1. Fork the repository.

  2. Clone your fork locally with git.

  3. Run make install (see Setting up the environment).

  4. Create a branch for your changes.

  5. Make your changes and ensure they follow the project style.

  6. (Optional) Run make lint or uv run pre-commit run --all-files manually to apply fixes and check types before committing.

  7. Commit your changes to git.

  8. Push the changes to your fork.

  9. Open a Pull Request.

    Important

    Give the pull request a descriptive title indicating what it changes. If it fixes an open issue, include the issue number. For example: fix: update user profile validation logic (#123).

Tip

All commits and pull requests must follow the Conventional Commit format — commit messages are parsed by git-cliff to generate the public changelog. Before pushing, ensure all tests pass by running make test.

Note

Every pull request is automatically verified by CI: pre-commit checks, the pytest suite with coverage, and CodeQL analysis. Changes to the documentation or application sources additionally trigger a strict Sphinx build.

Running the tests¶

The test suite requires Docker: the pytest-databases fixtures automatically spin up dedicated PostgreSQL and Valkey containers. No additional environment setup is needed — the committed .env.testing provides the required configuration, including a test-only JWT key.

make test        # Run the suite in parallel (2 workers)
make coverage    # Run tests and generate HTML/XML coverage reports

Project documentation¶

The documentation is located in the /docs directory and is built with ReST and Sphinx.

If you are unfamiliar with these tools, read the ReStructuredText primer and the Sphinx quickstart.

Docs theme¶

The project uses the Shibuya theme to maintain a modern and clean look. If you wish to contribute to the docs style or static site generation, please consult the theme documentation.

Running the docs locally¶

To work on the documentation with live-reload (recommended):

make docs-serve

The documentation will be available at http://localhost:8002.

Alternatively, you can build them with:

make docs

Community standards¶

  • This project follows the Code of Conduct. By participating, you are expected to uphold it.

  • Please do not report security vulnerabilities through public GitHub issues — see the Security Policy and contact the maintainer directly.

By contributing to IronTrack, you agree that your contributions will be licensed under the MIT License.
